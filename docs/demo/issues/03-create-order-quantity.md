## 현상

- `POST /orders`에 `quantity: 1.5`를 보내면 201로 주문이 만들어집니다.
- 그 결과 `totalAmount`가 `4500.5`처럼 소수로 저장된 주문이 있습니다. 정산에서 원 단위가 맞지 않는다는 문의가 왔습니다.

## 재현

```bash
curl -X POST "$API/orders" -d '{"customerId":"cust-1","items":[{"sku":"sku-a","quantity":1.5,"unitPrice":3000}]}'
# 기대: 400, 실제: 201
```

## 정해진 것

- 수량은 1 이상 1000 이하의 정수만 받습니다. 그 밖의 값은 400으로 거절합니다.
- 이미 저장된 주문의 데이터 정리는 이 이슈 범위가 아닙니다.

## 완료 조건

- 소수 수량, 0, 1001, 숫자가 아닌 값을 400으로 거절하는 테스트
- 정수 수량은 지금처럼 201로 저장됨
- `npm run verify` 통과
